GESTION UNDO ORACLE - GUIDE COMPLET
====================================


## 1. CONCEPTS FONDAMENTAUX UNDO

### 1.1 Définition
UNDO = données avant modification (rollback, read consistency)

Les données UNDO contiennent les anciennes valeurs des données modifiées pour permettre :
- Rollback des transactions
- Lecture cohérente (Read Consistency)
- Récupération après panne (Crash Recovery)
- Flashback Query

### 1.2 Historique et évolution
**Oracle 9i et versions ultérieures :**
- Introduction des tablespaces UNDO
- Remplacement des segments d'annulation traditionnels (rollback segments)
- Automatisation de la gestion des UNDO
- Contrôle précis de la rétention temporelle

**Avantages des tablespaces UNDO :**
- Simplification de l'administration
- Élimination des erreurs "snapshot too old"
- Gestion automatique de l'espace
- Rétention configurable des données historiques




## 2. CONFIGURATION UNDO

### 2.1 Paramètres d'initialisation critiques

**Paramètres essentiels :**

1. **UNDO_MANAGEMENT** (statique) :
```sql
-- Définit le mode de gestion
-- Valeurs possibles : AUTO (recommandé) ou MANUAL
-- Ne peut être modifié qu'au redémarrage
SELECT value FROM v$parameter WHERE name = 'undo_management';
UNDO_TABLESPACE (dynamique) :

sql
-- Spécifie le tablespace UNDO à utiliser
-- Peut être modifié en ligne
ALTER SYSTEM SET undo_tablespace = undotbs2;
UNDO_RETENTION (dynamique) :

sql
-- Durée de rétention en secondes (défaut : 900s = 15min)
-- Peut être augmenté pour éviter ORA-01555
ALTER SYSTEM SET undo_retention = 3600;  -- 1 heure
UNDO_SUPPRESS_ERRORS (dynamique) :

sql
-- Supprime les messages d'erreur des commandes obsolètes
ALTER SYSTEM SET undo_suppress_errors = TRUE;


### 2.2 Création d'un tablespace UNDO
sql
-- Syntaxe complète
CREATE UNDO TABLESPACE undotbs1
DATAFILE '/u01/oradata/undotbs01.dbf' 
SIZE 2G 
AUTOEXTEND ON NEXT 512M MAXSIZE 32G
RETENTION GUARANTEE;  -- Garantit la rétention

-- Vérification
SELECT tablespace_name, status, retention, contents
FROM dba_tablespaces 
WHERE tablespace_name LIKE '%UNDO%';


##3. MONITORING UNDO

### 3.1 Vue d'ensemble
sql
-- Taille UNDO tablespace
SELECT tablespace_name, SUM(bytes)/1024/1024/1024 AS size_gb
FROM dba_data_files
WHERE tablespace_name LIKE '%UNDO%'
GROUP BY tablespace_name;

### 3.2 Vue V$UNDOSTAT - Statistiques détaillées
La vue V$UNDOSTAT contient les statistiques collectées par intervalles de 10 minutes sur 7 jours maximum.

Structure de V$UNDOSTAT :

BEGIN_TIME : Début de l'intervalle (10 minutes)

END_TIME : Fin de l'intervalle

UNDOBLKS : Nombre total de blocs UNDO consommés

MAXCONCURRENCY : Nombre maximal de transactions concurrentes

TXNCOUNT : Nombre total de transactions

MAXQUERYLEN : Durée de la plus longue requête (secondes)

EXPSTEALCNT : Tentatives de transfert d'extents obsolètes

SSOLDERRCNT : Nombre d'erreurs "snapshot too old"


Requêtes d'analyse :

sql
-- Statistiques récentes
SELECT 
    TO_CHAR(begin_time, 'DD/MM HH24:MI') as periode_debut,
    TO_CHAR(end_time, 'DD/MM HH24:MI') as periode_fin,
    undoblks,
    maxconcurrency,
    txncount,
    maxquerylen,
    expstealcnt,
    ssolderrcnt
FROM v$undostat
ORDER BY begin_time DESC
FETCH FIRST 10 ROWS ONLY;

-- Taux de génération UNDO par seconde
SELECT 
    ROUND(MAX(undoblks/((end_time-begin_time)*3600*24)), 2) as "UNDO_BLOCK_PER_SEC"
FROM v$undostat;


## 4. TUNING ET OPTIMISATION

### 4.1 Dimensionnement optimal du tablespace UNDO

Méthode 1 : Basé sur UNDO_RETENTION

sql
-- Calcul taille nécessaire
SELECT 
    d.undo_size/(1024*1024) as "ACTUAL UNDO SIZE [MB]",
    SUBSTR(e.value,1,25) as "UNDO RETENTION [Sec]",
    ROUND((TO_NUMBER(e.value) * TO_NUMBER(f.value) * g.undo_block_per_sec) / (1024*1024), 2) as "NEEDED UNDO SIZE [MB]"
FROM (
    SELECT SUM(a.bytes) undo_size
    FROM v$datafile a, v$tablespace b, dba_tablespaces c
    WHERE c.contents = 'UNDO'
    AND c.status = 'ONLINE'
    AND b.name = c.tablespace_name
    AND a.ts# = b.ts#
) d,
v$parameter e,
v$parameter f,
(
    SELECT MAX(undoblks/((end_time-begin_time)*3600*24)) undo_block_per_sec
    FROM v$undostat
) g
WHERE e.name = 'undo_retention'
AND f.name = 'db_block_size';
Méthode 2 : Calcul UNDO_RETENTION optimal

sql
-- Calcul UNDO_RETENTION optimal pour taille UNDO fixe
SELECT 
    d.undo_size/(1024*1024) as "ACTUAL UNDO SIZE [MB]",
    SUBSTR(e.value,1,25) as "CURRENT UNDO RETENTION [Sec]",
    ROUND((d.undo_size / (TO_NUMBER(f.value) * g.undo_block_per_sec))) as "OPTIMAL UNDO RETENTION [Sec]"
FROM (
    SELECT SUM(a.bytes) undo_size
    FROM v$datafile a, v$tablespace b, dba_tablespaces c
    WHERE c.contents = 'UNDO'
    AND c.status = 'ONLINE'
    AND b.name = c.tablespace_name
    AND a.ts# = b.ts#
) d,
v$parameter e,
v$parameter f,
(
    SELECT MAX(undoblks/((end_time-begin_time)*3600*24)) undo_block_per_sec
    FROM v$undostat
) g
WHERE e.name = 'undo_retention'
AND f.name = 'db_block_size';
4.2 Formules de dimensionnement
Taille UNDO nécessaire :

text
Taille UNDO (octets) = UNDO_RETENTION × DB_BLOCK_SIZE × UNDO_BLOCKS_PAR_SECONDE
UNDO_RETENTION optimal :

text
UNDO_RETENTION (secondes) = Taille_UNDO_actuelle / (DB_BLOCK_SIZE × UNDO_BLOCKS_PAR_SECONDE)


## 5. PROBLÈMES COURANTS ET SOLUTIONS

### 5.1 ORA-01555: Snapshot Too Old
Causes :

UNDO_RETENTION trop court pour les requêtes longues

Tablespace UNDO trop petit

Activité UPDATE/DELETE intensive concurrente aux SELECT longs

Solutions :

sql
-- Diagnostic
SELECT 
    ssolderrcnt as erreurs_01555,
    TO_CHAR(begin_time, 'DD/MM HH24:MI') as periode
FROM v$undostat
WHERE ssolderrcnt > 0
ORDER BY begin_time DESC;

-- Correction 1 : Augmenter UNDO_RETENTION
ALTER SYSTEM SET undo_retention = 7200;  -- 2 heures

-- Correction 2 : Étendre le tablespace UNDO
ALTER TABLESPACE undotbs1 
ADD DATAFILE '/u01/oradata/undotbs1_02.dbf' 
SIZE 5G AUTOEXTEND ON NEXT 1G MAXSIZE 50G;

-- Correction 3 : Activer RETENTION GUARANTEE
ALTER TABLESPACE undotbs1 RETENTION GUARANTEE;

### 5.2 UNDO tablespace plein
sql
-- Vérification espace
SELECT 
    tablespace_name,
    ROUND(used_percent, 2) as used_pct,
    ROUND(tablespace_size/1024/1024, 2) as total_mb,
    ROUND(used_space/1024/1024, 2) as used_mb
FROM dba_undo_extents
WHERE used_percent > 90;

-- Actions correctives
-- 1. Ajouter un datafile
ALTER TABLESPACE undotbs1 
ADD DATAFILE '/u01/oradata/undotbs1_03.dbf' 
SIZE 10G;

-- 2. Nettoyage des segments inactifs
ALTER SYSTEM CHECKPOINT;

-- 3. Réduction UNDO_RETENTION temporaire
ALTER SYSTEM SET undo_retention = 1800;  -- 30 minutes
5.3 Transactions consommatrices d'UNDO
sql
-- Identification transactions problématiques
SELECT 
    s.sid,
    s.username,
    s.osuser,
    s.program,
    t.start_time,
    t.used_ublk as blocs_undo_utilises,
    t.used_urec as enregistrements_undo,
    ROUND(t.used_ublk * p.value/1024/1024, 2) as undo_mb,
    s.sql_id
FROM v$transaction t
JOIN v$session s ON t.ses_addr = s.saddr
CROSS JOIN v$parameter p
WHERE p.name = 'db_block_size'
AND t.used_ublk > 1000
ORDER BY t.used_ublk DESC;

## 6. BEST PRACTICES UNDO

### 6.1 Configuration recommandée
sql
-- Paramètres optimaux
ALTER SYSTEM SET undo_management = AUTO SCOPE=SPFILE;
ALTER SYSTEM SET undo_tablespace = UNDOTBS1 SCOPE=SPFILE;
ALTER SYSTEM SET undo_retention = 10800 SCOPE=SPFILE;  -- 3 heures

-- Pour bases très actives
ALTER SYSTEM SET "_undo_autotune" = TRUE SCOPE=SPFILE;
ALTER SYSTEM SET "_highthreshold_undoretention" = 86400 SCOPE=SPFILE;
 
### 6.2 Règles de dimensionnement
Base de données OLTP typique : 10-20% de la taille totale des données

Applications transactionnelles lourdes : 20-30% de la taille des données

Minimum absolu : (MAXQUERYLEN × UNDO_BLOCKS_PAR_SECONDE × DB_BLOCK_SIZE) × 1.5

Prévoir 25% de marge de sécurité

### 6.3 Monitoring continu
Surveiller v$undostat toutes les 10 minutes

Alerter si used_percent > 85%

Journaliser les erreurs ORA-01555

Réviser UNDO_RETENTION mensuellement

## 7. FLASHBACK ET UNDO

### 7.1 Flashback Query
sql
-- Utilisation des données UNDO pour les requêtes historiques
SELECT salary 
FROM employees 
AS OF TIMESTAMP SYSTIMESTAMP - INTERVAL '30' MINUTE
WHERE employee_id = 100;

-- Vérification disponibilité données
SELECT 
    oldest_flashback_scn,
    oldest_flashback_time,
    retention_guarantee
FROM v$flashback_database_log;

### 7.2 RETENTION GUARANTEE
sql
-- Activation (garantit la rétention UNDO)
ALTER TABLESPACE undotbs1 RETENTION GUARANTEE;

-- Désactivation (libère l'espace)
ALTER TABLESPACE undotbs1 RETENTION NOGUARANTEE;

## 8. MIGRATION ET CHANGEMENT

### 8.1 Migration UNDO MANUAL → AUTO
sql
-- 1. Vérifier le mode actuel
SELECT value FROM v$parameter WHERE name = 'undo_management';

-- 2. Créer UNDO tablespace
CREATE UNDO TABLESPACE undotbs_new
DATAFILE '/u01/oradata/undotbs_new.dbf' SIZE 10G
AUTOEXTEND ON;

-- 3. Modifier SPFILE
ALTER SYSTEM SET undo_management = AUTO SCOPE=SPFILE;
ALTER SYSTEM SET undo_tablespace = undotbs_new SCOPE=SPFILE;

-- 4. Redémarrer
SHUTDOWN IMMEDIATE;
STARTUP;

-- 5. Nettoyer ancien tablespace
DROP TABLESPACE undotbs_old INCLUDING CONTENTS AND DATAFILES;
8.2 Changement de tablespace UNDO en ligne
sql
-- Basculer vers nouveau tablespace
ALTER SYSTEM SET undo_tablespace = undotbs2;

-- Vérification
SELECT value FROM v$parameter WHERE name = 'undo_tablespace';
9. SCRIPTS UTILES
9.1 Script de monitoring UNDO complet
sql
SET PAGESIZE 100
SET LINESIZE 200
COL tablespace_name FOR A15
COL used_pct FOR 999.99

SELECT 
    TO_CHAR(SYSDATE, 'DD/MM/YYYY HH24:MI') as check_time,
    tablespace_name,
    ROUND(used_percent, 2) as used_pct,
    ROUND(tablespace_size/1024/1024, 2) as total_mb,
    ROUND(used_space/1024/1024, 2) as used_mb,
    status
FROM dba_undo_extents
UNION ALL
SELECT 
    TO_CHAR(SYSDATE, 'DD/MM/YYYY HH24:MI') as check_time,
    '--- STATISTIQUES ---' as tablespace_name,
    NULL as used_pct,
    NULL as total_mb,
    NULL as used_mb,
    NULL as status
FROM dual
UNION ALL
SELECT 
    TO_CHAR(SYSDATE, 'DD/MM/YYYY HH24:MI') as check_time,
    'UNDO_RETENTION' as tablespace_name,
    NULL as used_pct,
    NULL as total_mb,
    (SELECT value FROM v$parameter WHERE name = 'undo_retention')/60 as used_mb,
    'minutes' as status
FROM dual;
