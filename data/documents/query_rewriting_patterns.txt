PATTERNS DE RÉÉCRITURE DE REQUÊTES
===================================

1. SUBQUERY → JOIN

❌ LENT (subquery exécutée pour chaque ligne):
SELECT e.name FROM employees e
WHERE e.dept_id IN (SELECT dept_id FROM departments WHERE location = 'NY');

✅ RAPIDE (JOIN exécuté une fois):
SELECT e.name FROM employees e
JOIN departments d ON e.dept_id = d.dept_id
WHERE d.location = 'NY';

2. NOT EXISTS vs NOT IN

❌ LENT (NOT IN avec NULL problématique):
SELECT * FROM employees
WHERE dept_id NOT IN (SELECT dept_id FROM departments);

✅ RAPIDE (NOT EXISTS):
SELECT * FROM employees e
WHERE NOT EXISTS (
  SELECT 1 FROM departments d WHERE d.dept_id = e.dept_id
);

3. DISTINCT vs GROUP BY

❌ LENT (tri puis suppression doublons):
SELECT DISTINCT dept_id FROM employees;

✅ PLUS RAPIDE (agrégation):
SELECT dept_id FROM employees GROUP BY dept_id;

4. COUNT(*) vs COUNT(column)

✅ TOUJOURS utiliser COUNT(*):
- Plus rapide
- Compte toutes lignes incluant NULL

5. UNION vs UNION ALL

Si pas de doublons:
UNION ALL (évite tri de déduplication)

6. WHERE vs HAVING

Filtrer AVANT agrégation:
SELECT dept_id, AVG(salary)
FROM employees
WHERE salary > 50000  -- Filtre avant
GROUP BY dept_id;

Pas après:
SELECT dept_id, AVG(salary)
FROM employees
GROUP BY dept_id
HAVING AVG(salary) > 50000;  -- Seulement si condition sur agrégat
